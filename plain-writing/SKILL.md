# 正式文稿写作

## 写作规则

### 第一条｜禁止强行制造逻辑关系

1. **减少典型 AI 句式**：中文少用“不是……而是……”“并非……而是……”“不仅……更是……”“看似……实则……”“真正……在于……”“与其说……不如说……”；英文少用 `is not..., but...`、`not only..., but also...`、`more than just...`、`it is not just..., it's...`、`rather than...`。这些句式并非绝对禁止，但不应成为默认表达方式。重点在于，不要为了服务防御性免责语句，而强行加入。
2. **逻辑关系必须真实存在**：不强行制造转折、对立、递进或升华，不依靠关联词增强语气。只有确实存在否定、替代、对比或递进关系时才使用相应句式，否则直接陈述事实。
3. **避免空泛升华与刻意用词**：“本质”“真正”“核心”“从……到……”等表达应有明确的实际含义，否则删除或改为具体的对象、条件、范围及证据。不刻意使用生僻词、抽象词或不必要的专业术语，例如将普通的“基础”“范围”“限制”生硬替换为“基线”“边界”。确有明确技术含义时可以正常使用。
4. **准确、自然优先**：中文和英文写作均应优先保证事实准确、语义清楚和行文自然。学术英文尤其应通过明确的主语、动词、证据及限定条件表达观点，避免依赖华丽词汇和戏剧化句式。修改时不得为了规避某种句式而改变原意或削弱真实的逻辑关系。

### 第二条｜默认删除无必要的防御性话语

1. **默认直接陈述，禁止习惯性叠甲。** 防御性话语指不增加实际信息，仅用于规避质疑、降低语气、免责、自谦或填充过渡的表达。直接写工作内容、事实、判断、结果及其依据，不为可能出现的质疑预先辩解。删除“需要指出的是”“值得注意的是”“严格来说”“需要强调的是”等无实际作用的引导语，以及没有明确依据的“可能”“或许”“一定程度上”“不排除”等模糊限定。

2. **不主动解释没有做什么。** 正文应聚焦已经开展的工作和当前需要论证的问题。对于未开展的试验、未涉及的研究方向、未验证的工况、未实现的功能，不主动逐项说明，也不添加“尚未考虑……”“暂未开展……”“不代表……”“不意味着……”等预防性声明。只有这些信息直接影响当前结论的成立、使用或理解时，才予以说明。

3. **避免否定词密集与排除式表达。** 不连续使用“不”“未”“未必”“无法”“难以”“不能替代”等否定词，通过反复说明某项工作不涉及什么、某项功能不具备什么来界定内容。优先正面陈述实际功能、工作范围和结论，避免将功能说明写成否定清单。确实需要区分功能或说明限制时，应直接写明对应关系，不额外列举无关的排除项。

4. **已经交代的条件不重复声明。** 研究对象、试验环境、适用范围、模型假设和技术限制应在相关位置准确交代，后文由上下文自然承接。不要在每个结论后反复追加“在特定条件下”“仅适用于……”“不能推广至……”等限定。条件发生变化或直接影响当前判断时，再明确补充。

5. **禁止为了规避责任而弱化明确结论。** 具备充分依据时直接给出判断，不随意添加“可能”“似乎”“初步表明”“有望”等缓冲词。证据确实不足时，应准确表达不确定性，并说明必要的依据或条件。不使用模糊措辞掩盖事实不清，也不为了语气保守而降低已有结论的确定性。

6. **以删除为主，禁止换一种说法继续叠甲。** 修改时先检查上下文：如果删去某句话后，读者仍能正确理解结论，且不影响论证完整性，就直接删除。不要把删掉的免责声明改写后放回原处，也不要通过新增过渡句、补充说明或段末总结重新引入相同内容。对相邻段落进行整体检查，避免同一限制反复出现。

7. **必要限制准确说明，不作延伸辩解。** 对结论成立至关重要的模型假设、试验条件、证据不足、设备限制和安全要求，应在相关位置明确说明。说明到足以准确理解和使用当前结论即可，不进一步列举无关的例外、潜在质疑或假设性风险，不将必要的事实限制扩写成免责声明。

### 第三条｜规范标题与章节命名

1. **避免教学式、营销式标题。** 正式技术文档、研究报告和规格书中，优先使用简洁、准确的名词短语或技术主题作为标题。避免“为什么……”“什么是……”“如何理解……”等问答式标题，以及“探索新路径”“开启新篇章”“全面解析”等宣传或媒体化表达。不为追求新颖而刻意创造标题。
2. **标题承担分类和检索功能。** 标题应让读者快速判断章节包含哪类信息，优先采用行业通用、含义明确且可复用的命名方式。可参考 TI、MPS 等半导体厂商的技术文档：
   - **TI**：`Specifications`（技术规格）、`Detailed Description`（详细说明）、`Application and Implementation`（应用与实现）、`Layout Guidelines`（布局指南）、`Layout Example`（布局示例）。
   - **MPS**：`Pin Functions`（引脚功能）、`Operation`（工作原理）、`Application Information`（应用信息）、`PCB Layout Guidelines`（PCB 布局指南）。

   对于产品规格书、技术手册及系列化项目报告，应尽量建立统一的章节体系。同类内容使用相同或相近的标题，具体产品特性、设计方案和技术细节由正文展开，不因产品不同而频繁改变章节命名。
3. **控制标题层级与具体程度。** 标题的概括范围应与层级相匹配，上级标题描述主要内容类别，下级标题根据实际需要细分技术主题。避免将正文中的单个问题、设计细节或解释性内容直接提升为章节标题。同级标题应保持相近的命名结构和概括程度，避免重复上级标题已明确的信息。
4. **根据文档类型调整命名方式。** 系列规格书和技术手册优先考虑章节统一性与检索效率；单篇研究报告、学术论文和专题分析则应准确体现研究对象、分析内容或实际工作。标题必须与正文内容对应，不强制所有标题采用“技术对象+实际工作”的形式，也不要求不同类型的文档套用同一套目录结构。
5. 正文标题默认按层级编号。章标题使用 `1`、`2`、`3`，下级标题继承上级编号，例如 `1.1`、`1.1.2`，同级连续编号。用户或文档模板指定格式时，遵循指定格式。
6. **优先使用简洁、概括性的命名。** 章节标题、表格标题及表头应优先采用能够准确覆盖内容的单一名称，避免习惯性使用“XX或XX”“XX与XX”“XX及XX”等并列结构。若一个常用词即可概括所指内容，就不必罗列多个近义词或相关概念。例如，“型号或配置”简化为“型号”，“参数或配置”简化为“参数”，“型号或规格”简化为“规格”。确实包含不同类别且无法用单一名称准确概括时，可以保留并列结构。不要在已有准确概括词的情况下，仍然习惯性地堆砌多个名称。

### 第四条｜禁止修改痕迹污染，暴露写作与修改过程

1. **最终文档应当独立完整。** 正文直接陈述当前的工作内容、技术方案、研究目标和实际结论，不暴露提示词、写作指令、修改意见或文档生成过程。避免“根据你的要求”“按照指南要求”“结合前述修改意见”“本次调整后”等面向编写者的表述。文档应能够脱离编写过程独立阅读，不依赖读者了解历史版本或修改背景。
2. **禁止保留修改痕迹。** 编辑指令只用于改变文稿，不应转化为正文内容。删除就是删除，替换就是替换，重写就是重写，最终只呈现修改后的有效内容。不主动解释修改了什么、删除了什么或为什么不再采用原有方案，避免“现改为……”“原方案不再适用”“不再采用此前的……”“由原来的……调整为……”等表述。已删除的内容不得以解释、对比或补充说明的形式重新出现。
3. **确保最终版本前后一致。** 修改局部内容时，应同步检查相关段落、标题、引用和结论，清理旧版本遗留的表述、逻辑依赖及前后矛盾。不为了维持历史版本的连续性而保留无效内容，也不通过新增解释性语句交代修改经过。最终文稿应像直接写成的完整文章，而不是多轮修改记录的拼接。

4. **修改前检查内容依赖，修改后回读上下文。** 删除标题、合并段落、调整章节或移动图表前，应检查后文是否存在依赖该内容的指代、引用、论证前提或章节关系。修改后核对相邻段落、图表编号、交叉引用及相关结论，确保不存在失去指代对象、引用位置错误、逻辑断裂或内容遗漏等问题。

5. **区分原始材料与最终文稿。** 原始图纸、照片、历史方案及其他参考资料用于获取和核实信息，不应将资料来源背景直接带入最终正文。应直接陈述已确认的技术内容，避免无必要地使用“现场”“原柜”“原图”“根据照片”等来源性描述。文稿应能够脱离原始材料独立阅读，必要的正式引用、数据来源和技术背景除外。

### 第五条｜拒绝重复表达，车轱辘话，提高信息密度

1. **每句话应尽量提供信息增量。** 拒绝写大量“**正确的废话**”，句子应承担明确的表达功能，例如陈述事实、解释原因、提供依据、分析影响、提出方法或推进论证。避免用不同措辞反复表达同一观点，不通过同义替换、抽象概括或修辞扩展来凑字数。若删去某句话后，读者获得的信息和理解均无变化，应优先删除。

2. **避免段落和章节之间的车轱辘话。** 相邻句子不重复解释相同内容，不同段落应有各自的内容重点。已经交代过的背景、概念、条件和结论，由上下文自然承接，无需反复介绍。新增段落应推进论述，而不是将前文换一种说法重新展开。

3. **删除无必要的总结、铺垫和过渡。** 避免在每段开头机械地介绍背景、在结尾重复概括段落内容，或使用“综上所述”“由此可见”“通过上述分析可以发现”等套话制造结构感。只有总结能够提炼新结论、整合分散信息，或过渡能够建立必要的逻辑联系时，才予以保留。

4. **保持必要的解释和论证，不为简洁牺牲内容。** 信息增量不等于每句话都必须引入新事实。必要的原理解释、推导过程、举例说明和逻辑衔接同样有价值。应删除的是重复和空洞内容，而不是机械压缩字数；需要充分展开的地方应讲清楚，不为追求短句或高密度而损害可读性。

5. **合理分配表格与正文内容。** 表格优先用于呈现参数、数据、型号及其他适合横向比较的信息；需要展开解释的分析、判断和选择理由，通常由正文承担。避免在多个表格中重复列出相同数据，也不将大段论述直接塞入表格。表格应简洁、清晰，正文与表格相互补充，不重复表达相同内容。

### 第六条｜保持正式书面表达，避免设问与过度口语化

1. **避免设问、自问自答和口语化铺陈。** 正式文稿中直接陈述研究内容、技术问题和分析结论，不通过连续提问引出正文。避免“问题出在哪里？”“应该怎么解决？”“怎么起、怎么传、怎么恢复”等设问式表达，也不使用“先看……再看……”“搞清楚……”“说到底……”等口头讲解方式组织论述。应将问题转化为明确的研究对象、分析内容或技术任务。例如，将“异常从哪个环节起，沿供电与数据两条连接怎么传”改为“分析异常的触发环节及其沿供电链路和数据链路的传播路径”。

2. **避免将专业动词替换为口语词汇。** 不为追求自然、简洁或所谓的“人话”，刻意使用生活化、形象化的动词替代准确的书面表达。尤其避免在正式技术文档中使用“撑不起”“省掉”“答不上”“汇不成”“挤在”“靠”“看”“搭”“定去留”“接得住”“调得回来”“现成能用”“分开存”等表达。应根据具体语义选择“无法支撑”“省略”“难以解释”“无法汇总”“集中于”“通过”“分析”“构建”“确定是否保留”“满足要求”“恢复至目标状态”“可直接使用”“分别存储”等更准确的表述，不机械地进行词语替换。

3. **保持专业、自然、克制的书面语风格。** 去除 AI 腔不等于口语化，也不意味着使用生僻词、堆砌术语或刻意提高语言复杂度。优先使用该领域通行、含义明确的书面表达，句式保持自然流畅。避免为了增强感染力而使用夸张、比喻、拟人或具有表演感的叙述方式。最终我们追求是 TI、MPS 等技术资料中常见的风格：术语准确、句子直接、表达克制，读起来流畅，但没有口头讲解的痕迹。

### 第七条｜理清内容关系，组织论述逻辑

1. **先梳理内容，再组织语言。** 报告和文书写作应以实际内容和观点为基础，先明确需要表达的事实、背景、问题、依据、分析、方法及结论，再根据它们之间的关系安排章节和段落。避免按照材料提供顺序直接堆砌内容，或在缺乏整体规划的情况下逐段拼接。写作前应明确文章的论述主线，使各部分共同服务于文档的核心目的。

2. **根据真实关系安排内容顺序。** 识别不同内容点之间的因果、递进、并列、对比、总分及前提依赖关系，按照符合读者理解习惯的顺序展开。例如，技术研究报告可以从研究对象及其工作环境出发，介绍存在的问题、产生的影响，再引出研究必要性、研究内容及技术路线。具体顺序应由内容本身决定，不强制套用固定的论述模板，也不为了使结构完整而人为制造逻辑关系。

3. **保证段落之间的衔接与递进。** 每个段落应有相对明确的内容重点，相邻段落之间应存在可以理解的联系。前文为后文提供必要背景、条件或依据，后文在此基础上进一步分析或展开。避免话题突然跳转、前提尚未交代就直接给出结论，或不同内容之间缺乏必要的联系。优先通过内容本身建立衔接，不依赖“首先”“其次”“此外”“因此”等关联词强行拼接。

4. **兼顾整体结构与局部逻辑。** 不仅要检查单个句子的表达，还应关注句子之间、段落之间以及章节之间的逻辑关系。相互关联的内容尽量集中讨论，具有前提依赖的内容按照合理顺序展开，不同章节应有清晰的内容分工。必要时调整原有材料的顺序、合并相关内容或拆分不同主题，使文章形成连贯的整体，而不是若干独立观点的简单集合。

5. **确保技术对象指代明确。** 技术对象首次出现时，应提供足以识别其含义的名称、型号或必要定义。对于 P1、KM1、QF2 等设备位号，以及自定义缩写、代号，应在首次出现时交代对应对象，后文可直接使用简称或代号。避免使用只有作者或编写者才能理解的内部称谓，也不必在每次出现时重复完整名称。

### 第八条｜调整句式结构，保持自然的行文节奏

1. **避免长句连续堆叠。** 不将过多背景、条件、分析和结论集中在单个句子中。对于包含多层修饰、多个并列分句或复杂逻辑关系的长句，可在不破坏语义完整性的前提下适当拆分。句子长度应由内容复杂度决定，不追求机械统一。

2. **避免重复使用相同句式。** 不连续采用相似的句子结构、固定的列举方式或宣告式表达。减少不必要的冒号、分号及层层嵌套的并列结构，避免每个段落都以相同的方式引入、展开和总结。具有实际技术分类或逻辑对应关系的并列内容应保留。

3. **保持自然、稳定的书面表达。** 根据内容需要合理安排长短句。复杂原理和技术条件可以使用长句，明确的事实与结论可以直接陈述。不为制造节奏而刻意缩短句子，也不通过口语词汇、设问、修辞或夸张表达增加变化。

### 第九条｜中文报告正文版式

中文报告正文默认使用宋体小四（12 磅），段落首行缩进两个汉字。用户指定版式或提供模板时，按其要求排版。
